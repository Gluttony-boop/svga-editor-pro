
# SVGA Editor Pro

一款专业的 SVGA 动画编辑桌面应用，基于 Tauri 2 + React 构建。

## 功能特性

- **加载 SVGA** - 支持 URL 或本地文件加载，支持拖放
- **可编辑工程** - 保存/打开自包含 `.svgaproj`，保留关键帧、文字模拟、替换素材与画布参数，支持下次继续编辑
- **本机自动恢复与最近工程** - 编辑后保留可继续编辑的工程副本，重开时提示恢复；支持下载、删除及独立关闭自动记录，不上传素材
- **实时预览** - 高性能 Canvas 渲染，帧缓存 + 预计算，流畅播放
- **沉浸预览** - F9 收起编辑面板，保留播放/背景/缩放控制和文件信息；Esc 退出并恢复原视图，支持 1:1 原尺寸查看
- **FPS 与帧数调整** - 修改帧率和动画帧数，实时预览效果
- **图层管理** - 查看所有精灵图层，支持新增/删除/复制/排序
- **画布尺寸** - 修改 SVGA viewBox 宽高，支持锁定比例、校验像素上限、撤销/重做并同步预览与导出
- **关键帧编辑** - 图层属性轨道、当前帧位置/缩放/旋转/透明度、画布写入关键帧、移动/删除/缓动与撤销
- **图层查找** - 按图层名或资源名搜索，按显示/锁定状态筛选，一键定位选中图层
- **资源面板** - 资源搜索、按体积/名称排序、编码体积与解码内存估算、单图/批量 ZIP 提取
- **素材替换预览** - 先查看目标尺寸效果，再确认替换；支持等比适应、居中裁切填充和拉伸，支持撤销/重做
- **插槽配置** - 支持文本插槽（setText）和图片插槽（setImage）
- **文字模拟与 Key 检查** - 完整图片 Key、文字命名候选、引用定位；文案实时跟随动画，支持文字框宽高、字号、颜色与对齐，可选择仅模拟或将固定字形写入完整 SVGA 动画
- **图片压缩** - 保真 PNG、64/128/256 色 PNG 量化、WebP；支持按当前画布或指定最大宽高等比缩减图片纹理，不改变画布及动画坐标
- **优化预设** - 内置多种优化预设（无损/均衡/高压缩/自定义）
- **多格式导出** - SVGA / PNG 序列 / WebP
- **导出预览与对比** - 优化前后并排播放、逐帧检查、真实文件体积对比，确认后直接保存预览产物
- **专业交付包** - 将实际 SVGA、Key/文字接入清单、资源摘要、实际/设计预览、离线检查报告和校验值打成 ZIP；默认不附可编辑工程，目标播放器明确标为未实测
- **快捷键** - Ctrl+O 打开动画/工程、Ctrl+S 保存工程、Ctrl+Shift+S 工程另存为、Ctrl+E 导出、空格播放暂停
- **桌面更新入口** - 帮助 → 检查桌面更新；网页模式不会安装桌面程序，未配置生产公钥/HTTPS 端点时明确显示未配置，不伪报最新版
- **AI / MCP 控制** - 桌面端提供仅限回环地址的 MCP 服务，GPT 网页可通过配套扩展读取工程摘要、调整图层、控制播放、撤销/重做并请求保存或导出

## 安装使用

### 下载安装包

前往 [Releases](../../releases) 页面下载对应平台的安装包：

| 平台 | 文件 |
|------|------|
| Windows | `SVGA Editor Pro Setup x.x.x.exe`（安装版）或便携版 |
| macOS | `SVGA Editor Pro-x.x.x.dmg` |

### 从源码构建

```bash
# 克隆仓库
git clone https://github.com/Gluttony-boop/svga-editor_new.git
cd svga-editor_new

# 安装依赖
npm install

# 运行开发模式
npm run dev

# 运行 Tauri 桌面开发模式
npm run dev:tauri

# 网页版 + 本机 MCP（可选；PowerShell 先配置 API Key 才能使用 AI 生图导入）
$env:OPENAI_API_KEY="sk-..."
npm run dev

# 构建 Web 版本
npm run build:web

# 构建 Windows 版本
npm run build:win

# 构建 macOS 版本
npm run build:mac

# 构建当前平台
npm run build
```

## 使用指南

### 连接 GPT 网页（MCP）

启动 `npm run dev` 网页版后，打开“帮助 → 关于 SVGA Editor Pro”，开启“允许 ChatGPT 操作编辑器”。扩展源码位于 [`integrations/gpt-web-extension`](integrations/gpt-web-extension)：首次在 Chrome/Edge 中加载一次后，点击“自动连接本机编辑器”即可自动发现网页版 `5174` 或桌面版 `8765` 服务并配对，不再需要复制 MCP 地址和令牌。扩展只访问 `127.0.0.1`，不会把工程素材上传到云端。

网页版要使用 MCP，需要保持 Vite 开发服务运行；`vite.config.ts` 会同时启动本机 MCP HTTP 端点和 HMR 编辑器桥接。若要启用 `generate_and_import_image`，在启动前设置 `OPENAI_API_KEY`；该 Key 只在本机 Vite/桌面进程中使用，不会发送给浏览器扩展。

MCP 服务实现标准 JSON-RPC 2.0 的 `initialize`、`tools/list` 和 `tools/call`，当前工具包括读取工程摘要、画布截图、读取/替换图层素材、调用 OpenAI 生图、选中/更新图层、跳帧、播放控制、预览背景、撤销/重做、保存请求和打开导出面板。可用 `SVGA_MCP_PORT` 更换端口，用 `SVGA_MCP_TOKEN` 固定令牌；如需生图，在启动编辑器前配置 `OPENAI_API_KEY`。令牌和 API Key 不要提交到仓库。协议细节和安全边界见 [`integrations/gpt-web-extension/README.md`](integrations/gpt-web-extension/README.md)。

如果使用 ChatGPT 工作区的官方自定义 MCP 应用，需要把本机服务通过受控的 [Secure MCP Tunnel](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt) 暴露为远程地址；普通网页 ChatGPT 不能直接连接 `localhost`。本仓库的浏览器扩展适合个人本机使用，避免把编辑器端口公开到公网。

**保存工程与导出是两件事**：顶部“保存工程”或 Ctrl+S 保存 `.svgaproj`，保留可编辑关键帧、文字模拟和替换图片；“导出”生成交给播放器的 SVGA/图片，不清除工程未保存标记。可通过“打开文件”、拖入或桌面文件关联重新打开工程。格式、限制和恢复语义见 [工程文件](docs/project-format.md)。

顶部“恢复 / 最近”可查看本机副本。自动恢复默认开启：完成编辑后稍候备份，不打断播放，不提交正在输入的草稿，也不替代 Ctrl+S。关闭重开后若发现恢复副本，会显示提醒；打开副本后须保存为工程文件，不会自动覆盖原磁盘文件。副本仅保存在当前浏览器地址或桌面应用的用户配置中，不是云备份；清理浏览器/应用数据可能导致丢失。支持“立即备份”、独立关闭恢复/最近记录，以及二次确认后删除。容量与多窗口行为见 [本机工程库](docs/local-project-library.md)。

在右侧“插槽”中选择图片 Key，即可输入文案或点击“插入示例文字”查看实时效果。Key 清单区分图片资源、疑似文字命名和已配文字，不会把命名推测当作文件类型。文字与图片替换可以共存，草稿输入支持 Esc 取消和一次撤销。长文案可通过“文字框宽度/高度”或“加宽 100 px”扩大显示范围，不拉伸底图或字号；范围以源图左上角为锚点并跟随原动画变化，原遮罩、裁切路径和画布边界仍生效。

“SVGA 文字导出”默认**仅模拟**：配置过的范围通过透明扩容与逐帧布局写入 SVGA，但不写入文案。选择**写入 SVGA（固定字形）**后，当前启用且非空的文字会成为图片字形，保留完整动画，不是导出一张截图；关闭文字或清空文案时仍保留底图。已导出的字形不能作为动态文本直接改字，请同时保存 `.svgaproj` 保留可编辑文字。PNG/WebP 包含当前可见效果，JSON 仅交付配置，不证明任何 SVGA 已按该配置生成；接入前核对实际文件，避免重复叠字。详见 [图片 Key、文字范围与交付](docs/text-preview.md)。

新增 AE 风格的关键帧工作区：选择图层后切换“◆ 关键帧”，在开始帧记录数值，再到后面的帧拖动画布或输入位置、缩放、旋转及透明度。时间轴可展开属性、拖动菱形、输入帧位置、设置缓动；“整段调整”保留原来的全片段编辑行为。两种模式都保留原 SVGA 动画，预览与导出共用采样逻辑。操作、快捷键和当前边界见 [关键帧工作区](docs/keyframe-workspace.md)。

在属性面板“画布尺寸”中可以修改 SVGA viewBox 的宽度和高度；锁定比例会同步计算另一边。尺寸修改只改变合成边界，不自动缩放图层坐标，预览和导出保持一致。单边限制 8192 px、总像素限制 4,194,304，详见 [画布尺寸](docs/canvas-size.md)。

属性面板新增“对齐与分布”：六向对齐、水平/垂直等边缘间距，可选择当前选区或画布边界作为参考。单图层支持对齐到画布；等间距至少选择三层。排版会暂停并基于当前实际帧计算，只增加整段位置偏移，不改原角度、缩放或关键帧；一次操作一条撤销，已满足的排版不产生历史。含锁定、隐藏或无有效边界成员时整组禁用，负间距明确提示重叠。详见 [精确排版](docs/layer-layout.md)。

多图层编辑支持 Shift/Ctrl/⌘ 单击图层列表或时间轴名称追加/移除选择；画布支持 Shift 单击与空白拖动框选，Shift 拖框追加。多选后使用同一组选框移动、等比缩放、旋转，单次手势只有一条撤销，未选中图层不变。多选为临时选区，不是永久编组；包含锁定、隐藏或当前帧不可编辑图层时不会悄悄只变换一部分。框选采用 MIT 的 React Selecto，具体语义及验证见 [多图层编辑](docs/multi-layer-editing.md)。

属性面板新增“时间编排”：可将单层或多层整体提前、延后、依次错开，或重置时间偏移；关键帧与源素材帧保持不变，时间轴、实时预览和导出使用同一套输出时间映射。默认允许延长总帧数以保留尾部，也可关闭后严格拒绝越界操作。遮罩关联层按整体处理，音频暂不随图层偏移。详见 [图层时间编排](docs/layer-timing.md)。

画布支持直接编辑图片图层：V 选择、H 抓手、W 旋转，拖动选中区域移动，八向手柄缩放，旋转手柄调角度。等比/吸附可切换，Shift 临时等比或按 15° 旋转；画布获焦后方向键微调。替换图片后当前帧自动刷新，参数与右侧“整段变换”联动，单次拖动只产生一条撤销，Esc 取消。整段模式保留源帧运动而不生成关键帧；切换到关键帧模式则记录当前帧。通用交互采用 MIT 的 React Moveable；范围及验证见 [画布直接编辑](docs/canvas-direct-editing.md)。

资源卡片单击（或聚焦“查看素材”后按 Enter/空格）只打开素材详情，不再新增图层。详情展示大图、源资源尺寸/体积和引用图层；点击引用可选中对应图层，不改变动画内容。新增图层请使用卡片上的“添加为图层”按钮。替换确认会明确提示作用于引用该资源的全部图层，包含隐藏、锁定和遮罩引用；本批不提供“仅替换当前图层”。

撤销/重做按钮的悬停提示和编辑菜单显示具体操作名称。导出提示分别标记处理中、文件就绪、保存成功、取消、失败和结果失效，取消不再显示成功色。主 SVGA 导出预览在保存取消或写入失败后保留，可再次保存；编辑或配置变化后旧结果不能保存。详见 [第一批交互改进与验证](docs/first-batch-interactions.md)。

图片资源面板新增“体检”：按共享、遮罩、未引用、已配置及高内存筛选，支持“内存↓”排序和 JSON 检查报告。素材检查可并排查看源图与当前替换图，切换透明格/黑/白背景检查边缘；点击引用会清除图层筛选并滚动到目标，不改变播放帧或历史。高内存指单张源图按宽×高×4 估算 ≥ 4 MiB，仅用于排查；不含替换图、帧缓存与 GPU 开销，不是播放器兼容性判断。未引用资源不会自动删除；缺失 Key 需核对动态插槽或形状约定。详见 [素材检查与体检](docs/resource-inspection.md)。

界面采用灰黑工作区与粉色主操作强调。左侧保留图层和图片资源，右侧“检查器”通过属性 / 插槽 / 导出标签切换，各面板独立滚动并保留状态；标签支持左右方向键和 Home/End。顶部可直接保存、打开导出设置或重置面板尺寸，标题栏显示当前文件名。“播放速度”改为下拉选择；小窗口使用“适应画布”会为浮动画布工具条预留空间。

时间轴支持拖动刻度或轨道定位（自动暂停播放），左侧图层名称固定，点击名称只选中图层、不改变帧位置。输入帧号按 Enter 或失焦跳转，Esc 取消输入；帧号从 1 开始。轨道获得焦点后，左右方向键逐帧，Shift+方向键移动 10 帧，Home/End 跳首尾。Shift+滚轮横移，Ctrl/Cmd+滚轮围绕鼠标缩放；“自适应”适应完整动画，“定位”将播放头移入可视区域，“跟随”控制播放时自动滚动。顶部手柄可以拖动调整高度、双击恢复默认，也支持聚焦后上下方向键调整。条带表示图层 clip 区间，菱形仅代表编辑轨道里的真实关键帧，不再将导入动画的每一帧都画成圆点。展开图层后可编辑新增调整轨道的关键帧，支持插入、拖动、删除和缓动；旧预设只显示摘要。

新文件默认开启时间轴自适应，短动画也会铺满可用宽度，窗口变化时自动重算。手动缩放后保留每帧宽度，点击“自适应”恢复；刻度保留首尾帧，当前帧整列高亮。默认时间轴高度 280 px，普通行高 28 px；“紧凑”改为 24 px，“展开”临时放大时间轴，再次收起恢复之前高度。可用高度受窗口大小限制，缩小或收起后仍会将选中的图层保留在可视区域。

1. **载入 SVGA** - 文件菜单打开、Ctrl+O、或拖放 `.svga` 文件
2. **预览动画** - 空格键播放/暂停，拖动时间轴逐帧查看
3. **调整参数** - 在右侧属性面板设置 FPS（帧率）和帧数
4. **配置插槽** - 在插槽面板查询可用插槽名，配置文本或图片
5. **导出** - 点击顶部导出按钮或按 Ctrl+E，切换到右侧导出标签，再选择压缩方案、预览及保存

图层较多时，可在图层面板搜索名称或原始资源名（忽略大小写），并组合显示/锁定状态筛选。按 Esc 清空搜索；点击“清除筛选”恢复全部图层，点击“定位”清除筛选并滚动到当前选中图层。筛选不修改文件内容，保留原图层编号；筛选期间暂停拖拽排序，清除筛选后恢复。

图片资源面板支持按 Key 搜索、按名称或编码体积排序。“提取”将**当前搜索结果**中的图片打包为 ZIP（含当前替换图片），附带 `manifest.json` 记录 Key 与文件名的对应关系，不重新编码图片。单图下载也保留实际格式。面板体积和解码内存统计针对**源资源**，不含插槽替换；解码内存仅按宽×高×4 估算，不代表进程总内存或最终 SVGA 文件大小。

点击资源卡片上的“替换图片”，选择图片后可以先预览，再切换等比适应（完整显示、透明留白）、裁切填充（居中裁切并铺满）或拉伸（改变比例）。确认会应用预览中的同一张目标尺寸静态 PNG，不修改原素材尺寸和图层动画；取消不会修改文档。支持恢复原图、撤销和重做。该入口限制上传文件不超过 32 MiB，输出最多 4,194,304 像素；无法取得原素材尺寸时不允许替换，动态图片会定格为解码时的一帧。插槽面板的独立图片选择入口仍保留原有行为。

在右侧导出面板选好优化配置后，点击“生成导出预览”。弹窗分别显示**源文件 / 当前编辑未优化副本 / 优化结果**的真实字节大小，并从两个实际产物重新解码画面，支持同步播放、逐帧查看和透明/黑/白背景。体积收益以当前编辑的未优化副本为基准，文件变大时会明确提示。点击“保存此优化结果”直接保存已预览的文件，不会再次压缩；也可保存同一快照的未优化副本。编辑内容或配置变化后旧预览失效，需重新生成。预览不改变文档和撤销历史，仅对比画面，不播放音频；导出不会清除文档的未保存标记。

压缩配置统一放在“导出”面板，属性面板不再提供另一套压缩开关。预设同时更新名称和完整配置，并只产生一次撤销记录。PNG 使用“色数”控制有损量化，WebP 使用质量百分比；PNG 原生编码的质量百分比并不起作用。量化包括透明度，可能影响渐变、辉光和抗锯齿边缘，先预览再保存。

图片尺寸可以选择按当前画布自动限制，或输入指定最大宽度/高度（等比缩小，不放大、不裁切）；百分比、指定尺寸和画布上限同时开启时取最严格值。它们只改变导出纹理，图片编码没有变小或整包变大时会保留原图/未优化副本。

| 预设 | 图片处理 | 适用取舍 |
| --- | --- | --- |
| 保真 PNG | 不量化、不缩图 | 画质优先，已优化图片的体积收益可能很小 |
| 均衡 PNG | 256 色，不缩图 | 轻度有损，保持 PNG 兼容性 |
| 高压缩 PNG | 128 色，图片分辨率 75% | 更小，但细节可能变软 |
| 极限 PNG | 64 色，图片分辨率 50% | 明显有损，务必检查效果 |
| WebP | 有损 WebP，默认质量 85% | 需要确认目标 SVGA 播放器支持 WebP |

图片处理失败会保留原图片并显示原因；图片不更小则不替换，整包变大时保留优化前的编辑副本。替换素材读取失败会中止导出，避免悄悄带着旧图保存；取消保存不再报告成功，选定路径写入失败会明确报错。主 SVGA 导出在保存前进行结构校验。此次修复的复现命令、范围及样例数据见 [导出压缩修复记录](docs/export-compression-fixes.md)。

点击画布工具条的“沉浸预览”或按 F9，可在应用窗口内收起工具栏、左右侧栏和时间轴，集中查看动画（不是系统全屏，窗口标题栏和状态栏仍保留）。支持播放、逐帧、倍速、背景切换，以及“1:1”和“适应画布”。Esc、F9 或“退出沉浸预览”恢复编辑面板和进入前的缩放/平移位置；Ctrl+E 自动返回导出面板。模式切换不重新创建画布或修改编辑历史。窗口大小变化时自动适应；更换/清空文件时自动退出。加载提示或错误出现时仍会显示工具栏。

### 自动构建

Windows 可直接双击项目根目录的 `package-github.cmd`，或在终端运行：

```bash
npm run package:github
```

默认流程为：列出并扫描待提交文件 → 类型/Lint/测试/Web 构建检查 → 自动提交仓库当前全部更改 → 普通推送 → 触发 GitHub Windows 打包 → 等待、下载及校验安装包。包含新增、修改、删除及已暂存更改；不会自动打 Tag 或发布 Release。无更改不创建空提交，已有未推送提交也会正常推送。首次在默认分支使用时，配套工作流会随代码一起提交推送，不用先手动清理工作区。

先查看将提交哪些文件可运行 `npm run package:github -- --dry-run`：允许工作区有修改，但不联网、不读取凭据、不提交推送。仅打包干净且已推送的 HEAD 使用 `--no-publish`；明确忽略本地修改、只打包旧 HEAD 使用 `--allow-dirty`。默认操作会发布整个仓库当前更改，请先确认其中没有无关内容。准备、权限、安全检查和失败处理见 [GitHub 一键打包](docs/github-packaging.md)。

项目配置了 GitHub Actions，推送 tag 时自动构建并发布：

```bash
git tag v2.0.0
git push --tags
```
