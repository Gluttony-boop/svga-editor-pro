# 可继续编辑的 SVGA 工程（`.svgaproj`）

工程文件与导出的 `.svga` 不是同一种文件：工程保存未烘焙的编辑状态，供下次继续工作；SVGA 是交给播放器的交付产物。保存工程不会改变源 SVGA。文字默认仅模拟；显式选择“写入 SVGA”后，导出的动画会包含图片字形，但工程仍保留可编辑文案，不会把字形冒充为播放器原生文字协议。

## 使用方式

1. 打开并编辑 SVGA，按 Ctrl+S 或点击顶部“保存工程”，选择 `.svgaproj` 路径。
2. “工程另存为…”或 Ctrl+Shift+S 保存另一份工程；第一次保存不会覆盖输入的 `.svga`。
3. 下次通过打开文件、拖入文件或桌面文件关联打开工程。图层、关键帧、文字与素材仍可编辑，重新建立当前会话的撤销历史。
4. 交付时用“导出”，它不会代替工程备份，也不会清除未保存工程状态。

桌面工程写入先保存同目录临时文件并同步，再重命名替换；不先截断旧文件。浏览器支持 File System Access 时确认实际写入后标记已保存；不支持时发起工程下载，并保留未保存提示，因为网页无法确认用户最终保存成功。取消保存、写入失败或打开坏工程时保持当前工作。

手动工程存储、自动恢复与最近工程已接入。自动恢复使用同一份自包含归档格式，未完成的文字/画布输入事务不会被提交或备份；打开本机副本会保留未保存状态且不携带原文件路径。副本管理、容量与清理边界见 [本机工程库](local-project-library.md)。跨设备同步尚未实现。原生文件关联和新的写入命令需要重新打包后生效。

文件写入成功与本机缓存维护是两个独立结果：缓存空间不足或存储不可用不会把实际写盘成功误报成保存失败，应用会另行提示旧恢复副本未清理或最近工程未更新。若写入期间继续编辑，只将先前快照视为已写入，新修改仍保持未保存。

## 保存的内容

- 原始输入 SVGA 的完整字节，以及当前视频数据和 Key 重命名后的资源映射。打开工程不会通过重解原文件覆盖当前编辑数据。
- 所有图层及副本、可见/锁定状态、顺序、源逐帧数据、裁切、时间偏移、整段变换、预设轨道和独立编辑关键帧。
- 画布尺寸、帧率/总帧数覆盖、导出压缩与优化配置。
- 图片和音频资源的完整原始字节，包括尚未使用的素材。
- 同一个 Key 的替换图片与文字配置（含文字框、固定参考尺寸和仅模拟/写入模式）、检测到的 Key、当前帧和图层选区。

不会持久化 HTMLImageElement、ImageBitmap、AudioBuffer、File、Blob URL、来源绝对路径或文件句柄。它们由打开流程重新建立。工程名称仅保存文件名部分。撤销栈属于当前会话，不在本格式内；重新打开后从已保存状态建立新历史。

替换图片的 Data URL 和当前有效的本地 Blob URL 会转换为归档内二进制资源。远程 HTTP(S) 地址不能直接成为工程依赖：请先选择本地图片。打开工程只解析内嵌内容，**不请求网络**；恢复后的插槽图片为 Data URL，不依赖已失效的 Blob URL。

## 格式版本 1

容器采用普通 ZIP，内容只有 `manifest.json` 和程序生成的 `assets/00001.bin` 等资源条目，不使用用户的图片 Key 作为文件路径。

`manifest.json` 根对象包含：

| 字段 | 含义 |
| --- | --- |
| `format` | 固定 `svga-editor-project` |
| `formatVersion` | 当前为 `1`，不支持的版本直接拒绝 |
| `assets` | `{path, size, sha256}` 数组；`size` 为实际解压字节数 |
| `document` | `ProjectDocument` 的可序列化编辑状态 |

二进制字段使用 `{asset: "assets/00001.bin"}` 引用。资源映射、插槽字典使用 entries 数组，因此 `__proto__`、`constructor`、空白及其他合法 Key 不会成为原型属性或路径。完全相同的素材按逐字节比较复用一个资产，CRC 只用于定位候选；最终每个资产都有 SHA-256 摘要。

`document.videoItem.movie` 保存当前动画（不含重复的 images 二进制字典），`videoItem.buffers` 为 `{key, data}` 数组。读取后会同时恢复 `movie.images`（Uint8Array）和 `buffers`（ArrayBuffer），而 `videoItem.images` 为空，交给应用的解码/生命周期管理层完成加载。原生解析器不提供 movie.version 时，归档使用已有顶层 version 或 `2.0.0`；原生稀疏矩阵中的 null 与省略字段保持原样。

`document.slotConfigs` 使用 `{key, config}` 数组。`config.imageConfig` 中图片 URL 改为 `{asset: {asset: "…"}, mimeType, scaleMode}`；历史 `value` 字段若本身保存了图片，则改为 `{asset: {asset: "…"}, mimeType}`，读取时还原。`value` 若是文本则保持文本，图片与文字共存时不互相覆盖。

### 文字显示范围与导出模式

`config.textConfig` 保留既有文字、字号、字体、颜色、对齐、偏移、行高、启用和隐藏底图设置，并支持以下可选字段：

| 字段 | 含义 |
| --- | --- |
| `boxWidth`、`boxHeight` | 固定局部坐标中的文字显示范围，左上角与源图左上角对齐 |
| `referenceWidth`、`referenceHeight` | 第一次建立范围时记录的源布局参考尺寸，此后不随加宽操作改变 |
| `exportMode` | 缺省或 `preview` 为仅模拟；`bake` 为导出时将启用且非空的当前文字栅格化写入 SVGA |

四个尺寸必须全部存在或全部缺省，且为 1–8192 的整数像素。文字框面积、参考区域面积及 `max(boxWidth, referenceWidth) × max(boxHeight, referenceHeight)` 合成面积均不超过 4,194,304 像素。`bake` 必须有完整尺寸组；其他模式值、部分尺寸或超限区域会在保存与读取时明确拒绝，不截小、不猜测缺省参考。

参考为 100 × 50、文字框为 300 × 50 时，只扩展文字可用范围，不把底图或字号拉大。后续原帧布局若变为 200 × 100，显示范围也按原动画变为 600 × 100。保存的是固定纹理坐标关系，原逐帧运动、关键帧、`clipPath`、遮罩与 `viewBox` 裁切仍保留；范围不等于画布尺寸。

仅模拟模式导出 SVGA 时，已设置的范围通过透明扩容与逐帧布局写入，文案不写入；写入模式导出完整动画中的图片字形，不是当前帧截图。关闭文字或文案为空时保留底图和已配置的范围。两种模式的 `.svgaproj` 都保存可编辑配置，不会把工程本身替换成烘焙后的交付文件。仅重新打开带字形的 `.svga` 无法取回原始可编辑文案。

本次在 `formatVersion: 1` 下明确扩展字段校验。新读取器接受没有这些字段的旧工程，并保持其逐帧文字排版和仅模拟行为，不自动补新字段。**旧版本读取器严格拒绝新字段**，因此不是新旧版本双向兼容；需要继续编辑含新字段的工程时，应使用支持此扩展的版本。

## 安全与兼容边界

当前上限用于避免误导入或恶意归档耗尽内存：

- ZIP 文件不超过 **128 MiB**；条目不超过 **5000**（含 manifest）。
- manifest UTF-8 数据不超过 **32 MiB**；每个二进制资产不超过 **128 MiB**。
- ZIP 实际解压数据加上原始 SVGA 内层解压数据合计不超过 **256 MiB**；原始 SVGA 内层最多 **128 MiB**。
- 当前可编辑画布按编辑器限制：单边最多 **8192 px**，总像素最多 **4,194,304**；当前文档和预览 movie 宽高须一致。源帧里的 layout 不要求正尺寸，允许空帧和稀疏坐标。
- 帧数及时间索引绝对范围最多一百万；原始 protobuf 扫描最多两百万字段。过大的项目会明确提示，不会静默裁切。
- 在 `JSON.parse` 之前限制清单嵌套至 32 层、对象与数组合计一百万个，防止体积不大的空对象炸弹导致大量内存分配。

读取过程核对 ZIP 中央目录、本地头、条目实际大小、CRC 和资产 SHA-256；拒绝路径穿越、绝对路径、重复条目、未声明条目、重叠/隐藏数据、加密 ZIP、分卷、ZIP64 和符号链接。流式解压按实际产出字节限流，不能靠伪造 ZIP 大小字段绕过；原始 SVGA 的内层 zlib/gzip 也受限，并在不构建大量消息对象的情况下扫描 protobuf 结构。

所有文档字段按已知结构验证。重复图层/关键帧 ID、重复资源 Key、不合法数值/时移/轨道、缺失资源、重要未知字段均拒绝；不会偷偷删除未来版本字段后另存损坏工程。原始形状枚举支持 protobuf 的数值和字符串形式，原始片段的省略字段不会强制补零。

摘要和 CRC 用于发现传输或存储损坏，**不等于数字签名、版权保护、授权验证或加密**。能够改写整个 ZIP 的人也能重算摘要。不要在工程内放入激活密钥、私钥或账号凭据。

读取 API 不执行脚本、不创建 HTML、不落盘 ZIP 条目、不加载字体；字体名称保存在文字配置中，但字体文件不内嵌，跨机器没有相同字体时仍可能出现字形差异。浏览器及操作系统的图片/音频解码能力也会影响预览，应用解码层须另外控制像素预算并对失败回滚。

图片恢复额外限制累计 64 Mi 像素（约 256 MiB RGBA），同 Key 复用图不重复计数。PNG/GIF/常见 BMP 先读头检查尺寸；JPEG/WebP 暂在解码后检查，不能据此声称对浏览器内存做了绝对隔离。插槽图也实际解码验证，失败释放本次 URL 并保持原工程不变。音频原始字节和完整原轨道字段会保留；本轮不代表已经完成所有平台的音频同步播放验收。

Playwright 已在独立生产构建中验证：含关键帧、800×844 画布、文字和替换图片的真实工程下载；重新打开后的画布像素一致，仍能改关键帧、撤销及再次保存。损坏工程、取消保存、模拟磁盘写满均保持当前编辑。Windows 原子写入的 Rust 代码已通过本机编译元数据检查，但本机缺 MSVC 链接器，执行测试已加到 Windows 打包流程，尚未在本轮远端运行。

## 开发与回归

```ts
const file = await createProjectArchive(document)
const restored = await readProjectArchive(await file.arrayBuffer())
// restored 只有数据；成功解码全部所需资源后，才能原子替换当前编辑文档。
```

定向测试：`npx vitest --run src/core/project-archive.test.ts`。测试使用真实 ZIP、有效 protobuf/zlib 源数据和图片字节，覆盖编辑态往返、Key 重命名、特殊 Key、素材回填、替换图片与文字共存及恶意/损坏归档拒绝。文字范围扩展还覆盖两种模式及模式缺省的往返、旧字段兼容、边长/面积上限、部分尺寸组和缺少参考尺寸的写入模式拒绝。对新字段的扩展应升级或明确扩展本格式验证器，并增加往返测试，不能依赖 JSON 的隐式丢字段行为。
