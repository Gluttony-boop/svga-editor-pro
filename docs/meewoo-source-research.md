## 2. 最值得体验的功能

第一方 [帮助页](https://www.meewoo.me/help.md) 描述了以下工作流；该帮助页由部署版 `app.js` 的 `loadHelpContent` 加载。以下为文档声明，完整效果需使用合法持有的样例实测。

- SVGA 素材管理：按名称搜索、复制素材名称、单个替换，替换后预览并导出。
- 素材编辑：底图与文案的拖拽、缩放、对齐；帮助文档说明使用 Konva。
- 导出交互：显示进度，分别配置目标尺寸、帧率或透明背景；帮助页也列出大文件与长动画注意事项。
- 普通 MP4 的绿幕处理和多段变速属于另一条工具链，不建议因为参考站具备这些能力就直接扩张当前 SVGA 资源面板任务。

**本轮优先体验路径**：导入 SVGA → 素材图管理 → 搜索 → 核对缩略图、key、尺寸及内存信息 → 单图下载/替换/恢复。它与当前项目资源管理最相关，无须引入新编解码器。

### 重要口径：内存不是文件大小

MeeWoo 的 `extractMaterialList` 中，`fileSize` 虽然名字像文件大小，实际赋值为图片解码后的 `width × height × 4`，模板也将它标为“内存占用”。这是 RGBA 像素内存估算，不是 PNG/JPEG 编码字节，更不是整个 SVGA 文件大小。[实现证据](https://github.com/vincentline/MeeWoo.me/blob/f3a59e25cabe754edff7e1a66a81b3322c80a138/src/assets/js/core/app.js)

本项目若展示文件体积，应使用当前图片数据的实际编码字节，并标为“图片体积”或“编码体积”；若展示上述计算，应独立标为“解码内存估算”。两者不能混用，也不能用图片体积合计承诺最终 SVGA 大小。

| 候选改进 | 来源关系 | 建议验收重点 |

## 6. 本轮实际落地与验证

以下是本项目的实现记录，不是对参考站能力的额外声明。

- 在资源面板新增 Key 搜索、自然名称排序、编码体积升降序；操作始终绑定 Key，不重排资源源数据或图层。
- 分开显示当前搜索结果的源图编码字节合计和 RGBA 解码估算，明确不包含插槽替换，不代表最终 SVGA 大小或进程总内存。兼容只有尺寸信息、图片 data 为空的元数据资源，回退读取原 buffer。
- “提取”按当前搜索结果打包 ZIP，下载优先采用当前图片插槽替换，否则保留源图片字节；实际扩展名按图片签名/MIME 判断，附带 Key→文件名清单；处理路径字符、Windows 保留名与大小写重名。失败会报告对应 Key，不静默保存缺图 ZIP。
- 对替换图片的 data URL 在本地解码，避免把图片允许显示等同于 CSP 允许 fetch。
- 资源网格采用固定行高、可视区卡片和最多两个整行占位块，避免为每一个屏外资源创建占位 DOM；增加资源后也会重新测量滚动区域。
- 独立实现，没有复制第三方源代码，不新增编解码依赖。

验证记录：33 项单元测试通过，类型检查和 Web 生产构建通过；浏览器实测资源搜索/无匹配/清空、1,000 张模拟资源滚动与节点数量上限、筛选后 ZIP 下载；解析下载 ZIP，确认只有目标图片和清单，JPEG 替换图未被错误命名为 PNG。未执行桌面安装包及原生保存对话框验证。浏览器预览 Worker 原有 CSP 限制仍存在，不属于本轮资源网格与提取变更。

参考站实际体验使用了自制 3 素材、48 帧 SVGA 样例，没有上传用户项目素材；确认素材管理搜索能缩小结果，且能看到 Key、尺寸和单图操作。参考截图位于 `output/playwright/meewoo-resource-search.png`，本项目截图位于 `output/playwright/resource-management.png`。

## 7. 后续候选与进展

1. **已在后续迭代完成：导出前试算与结果预览。** 使用实际产物展示三种整包体积，独立解码并排播放；缓存产物直接保存，编辑/配置变化后失效。实现与验证见 [导出研究记录](meewoo-export-research.md)。
2. **已完成素材替换前的适配预览**：资源卡片选择图片后，实时生成等比适应、居中裁切填充或拉伸后的目标尺寸 PNG，确认才应用；取消不改变文档。保存稳定数据地址供撤销、重做及恢复原图使用，原素材或插槽在预览期间变化时禁止应用旧结果。Key 复制及自由拖动裁切区域尚未实现。
3. **已完成应用窗口内的沉浸预览与文件信息汇总**：收起工具栏、左右面板和时间轴，保留窗口标题栏/状态栏；F9 进入或切换，Esc/显式按钮退出，退出时恢复原缩放和平移。保留播放、背景与缩放，增加 1:1 按钮及文件名、尺寸、FPS、帧数、时长、源文件体积。未调用浏览器或系统全屏 API。
4. MP4、双通道 MP4、GIF 等编解码属于独立扩展，需另评依赖体积、内存、音频同步及兼容性，不在本轮直接移植。

### 素材替换预览验证补充

- 本次独立实现几何计算和 PNG 生成，未复制第三方源码。原有导出器已经会写入图片插槽；将适配结果先生成到原素材尺寸，避免仅保存适配模式但导出器未应用的差异。
- 上传上限 32 MiB；输出最多 4,194,304 像素且任一边不超过 8192，来源图片超过 33,554,432 像素时拒绝处理。未知、零值或非整数目标尺寸不会回退为 1×1。
- 解码支持取消及超时；模式变化或关闭弹窗后丢弃旧任务，临时输入 URL 随弹窗生命周期释放，确认后的 PNG 数据地址不依赖临时 URL。处理期间不会写入历史；确认仅提交一次。
- 55 项测试、类型检查、lint 和 Web 构建通过。浏览器使用自制三色 PNG 验证三种模式的像素、取消不改变文档和历史、快捷键隔离、确认数据等于显示预览、撤销/重做后图片可解码；导出 SVGA 后重新解析，确认 720×760 目标尺寸、透明留白及中心像素正确。
- 截图：`output/playwright/material-replacement-preview.png`。未测试 Tauri 原生文件选择对话框；插槽面板独立入口没有在本轮迁移至新流程。

### 沉浸预览验证补充

- 补齐上一轮解码超时、预先取消、来源图片超限的边界测试后再继续实现视图功能；本轮总计 61 项测试，类型检查、lint、Web 生产构建通过。
- 侧栏与时间轴只改变显示状态，不卸载其组件；主 Canvas 不重建。沉浸视图保留临时进入前的缩放/位置快照，与文档历史分离。窗口变化时自动适应当前画布；换文件或清空文档自动退出，不把上一文件视图写给新文件。
