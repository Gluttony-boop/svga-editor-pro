# 桌面授权时间边界

桌面授权由服务端签发 Ed25519 lease。lease 有两个时间：短期 `exp` 用于离线使用，`licenseExpiresAt` 是绝对截止时间；刷新只能重新签发短期 lease，不能延长绝对截止时间。小时按 3,600 秒、天按 86,400 秒计算，首次激活时间以服务端时间为准。

## 本机时间处理

原生层验签后把许可编号、签名 `iat` 和墙上 UTC 时间写入系统安全存储的 `lease-clock-v1`。读取状态时会同时检查：

- JWT 签名、`kid`、issuer、audience、设备摘要和完整时间范围；
- 持久化时间高水位，墙上时钟回拨不会让有效时间倒退；
- 当前进程的 `Instant` 单调计时，运行期间回拨不会延长 lease；
- 墙上时间回拨超过 5 分钟时返回 `clock-suspect`，需要联网校时或刷新；
- 缺少、损坏或与当前许可不匹配的时间锚时，不开放高级能力。

过期的已签名 lease 仍可被读取以显示“已过期”，不会被误报成“签名损坏”。到期、吊销、时钟异常和断网都不删除工程，也不阻止打开、保存和迁出已有成果；高级能力读取 `advancedEnabled=false`。

## 仍然需要服务端的边界

`Instant` 只在当前进程有效。用户删除或复制整套系统安全存储、回滚虚拟机快照、修改二进制或长期离线重装时，客户端无法单独证明真实时间。签名租约、设备绑定和服务端吊销可以降低风险，但不能承诺“不可破解”。恢复这些场景需要重新联网刷新；正式上线还要完成设备密钥/PoP、换机、退款和人工找回流程。

## 验证

纯时间策略在 `src-tauri/src/license_clock.rs` 中测试了小幅回拨、大幅回拨、前进和许可绑定；`tools/native-license-core` 会在 Windows 与 Linux CI 复用授权验签和时间策略测试。完整桌面验收仍需在每个目标系统检查 keyring、休眠、重启、断网和到期提示。
