# 专业 SVGA 交付工具：产品路线图与商业验收

制定日期：2026-09-20。状态：商业化方案与验收标准；不是已上线功能、定价承诺或收入预测。本文不擅自给现有功能加锁、不执行收费、不部署第三方账户，也不更改代码许可。

## 产品承诺

让动效设计师把已有 SVGA 安全地改成客户需要的版本，次日还能继续改，交付给开发时能说清楚“文件是什么、哪些 Key 可替换、在哪个环境测过”。“像 AE”应体现在编辑语义、快捷操作和可恢复工程，而不只是面板排布。

优先人群和竞品依据见 [竞品研究](competitive-research.md)。首要结果是**一次有效交付及后续复用**，不是激活码发了多少或用户停留多久。

## 1. 路线图与完成定义

| 阶段 | 交付范围 | 必须通过的验收 | 不应声称已完成的内容 |
| --- | --- | --- | --- |
| M0：商业基础 | 竞品与用户任务证据、权益/时长语义、签名授权与桌面签名更新方案、许可与成本清单 | 小时/天数、首次激活/到期规则可解释；更新与授权密钥分开；无密钥也能安全开发；失败不会丢工程；列出需要经营者配置的外部资源 | 没有部署和真实设备验收前，不称“已可收款销售”“永不破解” |
| M1：可继续工作的工程 | 自包含工程文件、版本化格式、项目保存/打开、缺资源提示；随后增加自动恢复与最近工程 | 修改关键帧、图层、尺寸、文字和图片后保存，重启再开，编辑语义和画面一致；损坏/过大/新版本工程有明确提示且不破坏当前文档 | 普通 SVGA 是运行时产物，不能冒充无损编辑工程；首版手动保存不等于已有自动恢复 |
| M2：专业交付包 | Key/样式/图片映射清单、SVGA 与模拟预览分离、目标规格、校验值、检查报告与本地 ZIP | 收件人仅凭交付包知道如何接入和复核；未配文字、字体差异、未知播放器均明确显示；重复导出可追溯到工程修订 | 不声称 JSON 可被所有 SDK 直接导入，不声称模拟文字已写入 SVGA |
| M3：模板与批量变体 | 将允许变化的字段保存为模板；CSV/JSON 映射到昵称/头像；逐项预检、抽样预览、队列、重试与恢复 | 用 20 行样例生成对应结果；缺 Key/缺图/超长文案可定位；只重试失败项；中断后可恢复，旧成果不被覆盖；取消确实停止后续任务 | 文字要输出到 SVGA 须先明确选择动态配置交付或实现显式烘焙，不可把模拟截图等同于动画本体 |
| M4：指定播放器验证 | 可版本化目标档案、静态结构检查、实际产物回读、选定播放器对照、问题帧定位 | 报告写明 SDK/分支/版本、操作系统、检查项；已测/失败/未测分开；遮罩、透明边缘、WebP 与动态字分别验收 | 浏览器能播放不等于 Android/iOS/低端设备通过；内存估算不等于峰值实测 |
| M5：可销售闭环 | 经确认的套餐与价格、到期/换机/退款流程、更新发布演练、支持入口、试用任务研究 | 从领码、首次激活、使用、续期到支持均可走通；到期保留项目访问与安全保存；真实旧安装版能升级新签名版 | 不以“有激活窗口”代替交易、售后、可用性和许可清理 |

各阶段应拆成可单独验证的小迭代。M0 的研究、协议与测试骨架可以与 M1 并行；收款、启用限制与生产发布要等经营者确认。未验收项目保持未完成，不因目标模式持续运行就自动推定上线。

### M1 工程的最低内容与边界

- 保存原始 SVGA 字节及编辑层，而不是只保存已烘焙的产物。编辑层至少包括图层身份、顺序/显隐/锁定、源引用、整段变换、时间偏移、编辑关键帧、画布尺寸、FPS/总帧数、图片替换、文字模拟与导出设置。
- 工程资源应自包含，不能依赖关闭后失效的 `blob:` URL 或临时内存地址。字体文件不默认打包；保存字体名及不可移植提示，避免未经许可分发字体。
- 文件有格式标识、schema 版本和资源大小约束；未知版本拒绝或以安全只读方式打开，不静默丢字段。导入完成校验后再替换当前状态。
- “保存工程”与“导出 SVGA”分开命名和脏标记；导出运行时文件不应造成用户误以为文字配置与可编辑轨道已备份。切换/关闭文档时区分未保存工程与未导出产物。
- 自动恢复另设显式能力与测试：崩溃、磁盘满、浏览器存储配额不足、清理缓存等场景都应有边界。恢复副本不能覆盖用户最后一次主动保存。
- 验收夹具覆盖共享 Key、复制层、遮罩、音频、负/正偏移、非默认画布、特殊 Key、文字与图片共存。保存前后比较结构与多帧像素，允许明确记录的字体跨平台差异。

### M2 交付包最低清单

已实现的首版交付包包含运行时 `animation.svga`、`manifest.json`、`slots.json`、实际/设计预览图、`report.json`、离线 `README.html`、接入说明、资源摘要和 `checksums.sha256`；默认不附源工程，勾选后才分享 `.svgaproj`。ZIP 路径使用安全序号，不使用用户 Key 作为文件名。

交付清单记录最终产物摘要、canonical 工程修订、画布/FPS/帧数、实际输出 Key、共享引用、精确源图层、动态/固定字形状态、资源尺寸预算、目标配置和未测项。动态文字仍由目标端 API 配置；固定字形明确为不可动态替换的图片。报告会把结构通过、预算失败、字体差异和目标播放器未实测分开显示。默认不收集、不上传用户素材。

## 2. 付费层级：卖新增效率，不扣住已有成果

以下是供访谈和试用的结构候选，不是已生效套餐。先验证用户到底为省时、避免返工还是交付规范付费，再确定金额、设备数和周期。

| 候选层级 | 可感知价值 | 边界原则 |
| --- | --- | --- |
| 基础使用 | 当前已有编辑、单件预览/导出；工程可安全保存、打开 | 不追溯锁定用户现在已有的功能，不给既有作品加水印；基础故障修复不是额外收费点 |
| 项目通行证（小时/天） | 临时项目所需的新增专业能力，适合外包或偶发集中工作 | 激活前明确开始方式、绝对到期时间与权限；不暗中自动续费，不把排队失败当使用成功 |
| 专业版（周期） | 持久模板、批量变体、可复用交付规则、进阶验证与支持 | 在提供可测的持续价值后再收费；不按一次拖动或一次查看收次数 |
| 团队版（后续） | 团队目标规范、模板共享、版本责任、设备管理与支持 | 暂无后端/管理体系时不出售还不存在的云协作或审计能力 |

定价研究可以用真实任务做意愿测试和小规模付费试点；不得把问卷赞同当作购买。没有获得实际订单前不发布“转化率提升”结论，不默认选择年付或隐藏取消入口。

## 3. 激活与到期的产品语义

1. **许可激活和产品激活分开**：前者是兑换权益，后者是用户成功完成一个有用任务。不能把成功兑换等同于产品有价值。
2. 小时/天数建议定义为连续墙上时间；“1 天”明确等于 24 小时，统一用可信 UTC 计算并显示本地到期时间。不能每次启动重新计时，也不能把自然日和 24 小时混用。
3. “从签发开始”适合预定时间授权；“首次兑换开始”更适合出售待用激活码。后者需要可靠的一次兑换状态，不能只在客户端写个首次打开时间。生产采用哪种方式应由经营者确认并写入购买前说明。
4. 离线宽限应展示上次校验和最晚可离线时间。小时级许可不能拥有超过剩余权益的隐形宽限；网络暂时失败不可删除文件、退出应用或破坏正在保存的结果。
5. 到期关闭的是新增专业操作，不是用户文件的所有权。允许打开、备份、迁出项目和访问已生成的结果；续期后恢复权益，不要求重新做工程。
6. 设备绑定、换机、撤销、误判时间、丢码与退款需要可操作的支持流程。不收集不必要的硬件/个人信息，不把有问题的授权直接定性为盗版。
7. 客户端软件不能承诺绝对不可破解。商业目标是降低盗用与分享成本，同时保持正版体验；签名正确只说明票据未被篡改，不代表客户端执行逻辑永远不会被绕过。

以上为产品验收约束，具体密码学协议、服务部署和密钥轮换应以配套技术设计为准。无需自购服务器不等于可以没有远程可信状态；小时级到期、兑换次数和设备上限的强约束不能只靠一个公开静态网页。

## 4. 桌面更新与网页发布的体验标准

- 网页通过版本化构建部署；检测到新版本时，先提醒保存工程再刷新，避免热更新清空正在编辑的状态。静态托管不是强制清缓存的借口。
- 桌面需要明确的检查、下载、签名校验、安装/重启状态；校验失败不得继续安装。更新签名密钥与授权签名密钥分别管理。
- 编辑中发现新版本时可以延后。必须先保存工程并解释是否需要重启；不能为了更新自动结束未保存会话。
- 稳定版与测试版分开；发布说明写清格式迁移和回退限制。至少用真实旧版安装包演练一次升级，单元测试或下载到 EXE 不能替代安装升级验收。
- 无自有服务器阶段可评估托管发布资源与 Serverless 授权；实际地域可达性、费用、平台条款、域名与账户权限必须验证。不能将免费额度理解为永久零成本承诺。

## 5. 从首次成果到复用的非操纵漏斗

| 阶段 | 体验设计 | 可检验事件与指标 | 防误判/隐私边界 |
| --- | --- | --- | --- |
| 首次理解 | 选择“替换礼物头像”“修改动效”“检查交付”等任务；可跳过引导；内置获授权样例 | 样例打开率、导入失败率；用户是否能说清目标 | 导入成功不算完成；不强制上传文件或注册 |
| 首次成果 | 选 Key、看到实际变化、检查一帧、保存工程并导出结果 | 首次有效成果时间；从打开到成功保存/导出的完成率 | 取消保存不计成功；演示与真实项目分开统计 |
| 再次复用 | 最近工程、恢复、复制为变体、保留目标设置 | 7/28 天内不同会话重开并继续编辑的比例；第二次任务用时 | 软件启动和页面停留不等于复用；浏览器清缓存与样本丢失单列 |
| 愿意付费 | 完成免费任务后展示新增批量/交付价值，可先预检和看样例；价格/到期清楚 | 实际尝试高级任务、完成试用、购买与退款；按有需求用户分组 | 不虚构倒计时，不在用户已投入大量工作后突然锁保存；不把全体访问者当潜在付费分母 |
| 持续付费 | 可复用模板、可靠更新、明确售后、易取消/续期 | 后续项目复用、续期、故障工单、退款与离开原因 | 不收集图片、文案、Key、路径、激活码或设备标识用于营销分析 |

没有服务器时，先提供本地可查看/清除的使用统计或访谈记录，用户明确选择后导出给研究者；不要私自添加遥测。后续联网统计必须说明目的、字段、保留时间与关闭方式。

## 6. 试点实验与停止条件

建议首批招募 5–8 名真实设计师/技术美术；这是研究计划，不是已有用户数。选取获授权的简单、共享资源、多遮罩与较大体量样例，和用户现用方法执行相同任务。

- **任务 A：单次改版。** 换头像/昵称，改尺寸，导出并保存工程。目标假设：用户无需讲解能找到关键操作，首次成果可在约 5 分钟内完成。先测基线再调整，不对外承诺该时间。
- **任务 B：次日继续。** 关闭应用后重新打开，修改上一版的一处关键帧和文字。验收重点是无状态丢失、无需重复配置，不只是画面相同。
- **任务 C：20 个变体。** 使用同一清单比较总用时、人工点击、错配、失败重试、命名准确性；将首次模板设置时间计入，不只比较第二次运行的最佳速度。
- **任务 D：交给开发。** 不口头补充，让接收者凭交付包找到 Key、选定产物并复核结果；记录追问和退回原因。

先修可靠性，再看转化：出现丢工程、静默漏字/漏图、产物与预览不符、到期扣住作品或更新破坏安装，停止扩大付费试点。无法降低任务成本时，应调整功能和人群定位，不靠更多弹窗补救。

采用一致口径记录样本数、失败、取消和置信度；小样本结果只能说明可用性线索。不能从几次顺利演示推导市场转化率，更不能保证“用户一定愿意付费”。

## 7. 经营者必须确认的外部决策

进入正式销售前，仍需确认：历史与新增代码的授权边界、商业主体与支付/退款流程、套餐金额与设备数、许可开始规则、离线宽限、服务地区与托管账户、更新发布地址及签名密钥保管人。

这些不妨碍本地工程可靠性、交付包和授权/更新接口的开发；但缺少它们时应保持开发/测试状态，不暗中开启收费限制、发布生产许可证或承诺远程服务已上线。
