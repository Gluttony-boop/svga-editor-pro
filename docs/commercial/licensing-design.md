# 商业授权设计：托管激活码与限时离线凭证

核对日期：2026-09-20。适用产品：SVGA Editor Pro 桌面版。

状态：设计与最小服务原型，不是已经上线、可以直接收费的完整授权系统。本阶段不真实部署、不生成生产密钥、不启用支付，也不在现有编辑器中开启收费功能限制。本文的协议约束用于指导实现和验收；具体启用时间、商品价格和收费功能范围仍需产品负责人确认。

## 1. 结论与边界

建议采用 **Cloudflare Workers + D1 托管授权服务，默认一张码绑定一台设备，首次在线激活开始计时，短期签名凭证允许有限离线使用**。这不需要购买或维护一台自建服务器，但仍然有后端、云账户、网络依赖、配额和运营责任。

不能承诺“不可破解”。签名可以使未持有私钥的人难以伪造授权数据，但不能使用户控制的桌面程序成为可信环境。攻击者可以修改程序跳过校验、替换内置公钥、复制设备标识和本地状态；纯离线程序也无法可靠获知真实时间。Keygen 的官方安全说明同样明确指出，离线时钟不可信，需要定期在线核验；不能把“签名未被篡改”说成“客户端绝不会被破解”。[Keygen：安全与时钟篡改](https://keygen.sh/docs/api/security/)

| 风险 | 本方案能做什么 | 仍然不能保证什么 |
| --- | --- | --- |
| 修改授权截止时间 | 验证服务器 Ed25519 签名，拒绝改动后的凭证 | 程序被完整补丁修改后仍强制执行验证 |
| 本地时间回拨 | 使用服务器 UTC、进程内单调时钟和上次可信时间；异常时要求联网 | 离线重启、虚拟机快照回滚、删除或克隆所有本地状态后的真实时间 |
| 一码多人用 | 服务端原子绑定一个 `deviceHash`，拒绝不同设备首次抢占 | 复制相同设备标识、刷新凭据甚至整台虚拟机后的物理设备唯一性 |
| 撤销已发凭证 | 停止刷新，在线客户端及时获知撤销 | 让已经离线的客户端立即知道撤销；正常客户端最迟到现有 lease 结束 |
| 私钥或管理令牌泄漏 | 最小权限、密钥分离、轮换和审计 | 泄漏发生前后的损害自动消失，或旧版离线客户端即时得知密钥撤销 |

安全边界必须公开：这是一套提高滥用成本、管理合法授权的机制，不是绝对 DRM。混淆、完整性检查和原生校验只能增加修改成本。代码签名保护安装包来源，不等价于防破解。

## 2. 组件与信任关系

| 组件 | 职责 | 不应保存的内容 |
| --- | --- | --- |
| 桌面客户端 | 输入激活码、显示到期状态、验证短期凭证、保护用户成果 | 授权签名私钥、发码管理员令牌、Cloudflare 管理令牌 |
| `license-worker` | 激活、刷新、UTC 时间判定、签发凭证、管理接口 | 用户工程、图片、动画原始文件；不需要上传这些内容 |
| D1 | 激活码摘要、期限、设备绑定、撤销状态、必要的管理审计 | 明文激活码、签名私钥、明文刷新令牌 |
| Workers Secrets | 签名私钥、独立的刷新凭据密钥、独立的管理员令牌 | 任何必须公开给前端的配置 |
| GitHub / R2 | 构建与分发安装包、更新清单和公钥版本 | 用户授权秘密、发码清单、授权数据库、任何生产私钥 |

GitHub Pages 是静态托管；静态 JSON 只能分发版本或公钥，不能承担可靠的在线授时、第一次激活写入、并发占用或撤销判定。GitHub Actions 也不是面向每次授权请求的在线 API。不能用公开仓库中的“注册码列表”替代授权服务。[GitHub Pages 说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## 3. Cloudflare 可行性、额度和成本

下表为核对日官方文档所列额度，不是永久价格承诺；购买或上线前应再核对账户中的实际计划。

| 项目 | 核对结果 | 对本项目的含义 |
| --- | --- | --- |
| Workers Free 请求 | 每账户每天 100,000 次，UTC 午夜重置 | 激活、刷新、健康检查和滥用流量都应计入容量规划 |
| Workers Free CPU / 内存 | 每次请求 10 ms CPU，128 MB 内存 | 小型签名 API 有可行性，但必须实测密码运算与冷启动；不能用免费配额承诺性能 |
| D1 Free 读 / 写 | 每天读取 500 万行、写入 10 万行 | 计费单位是扫描/修改的行，不是 API 请求数；摘要查询必须建索引 |
| D1 Free 存储 | 账户共 5 GB，单数据库最多 500 MB，最多 10 个数据库 | 授权元数据很小，但不要把下载包、日志正文或工程放入 D1 |
| Workers Paid | 账户最低 5 美元/月，包含额度后另计用量 | 不是“每月最多 5 美元”，升级前需独立确认预算 |

请求与运行限制依据 [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/)，Workers 费用依据 [Workers Pricing](https://developers.cloudflare.com/workers/platform/pricing/)，D1 用量与存储依据 [D1 Pricing](https://developers.cloudflare.com/d1/platform/pricing/) 和 [D1 Limits](https://developers.cloudflare.com/d1/platform/limits/)。D1 免费日读写配额耗尽后查询会报错，不能把这种错误当成授权到期或自动赠送新期限。

容量示例仅为估算：若每 5 分钟刷新一次，100 名用户各使用 8 小时约产生 `100 × 8 × 60 ÷ 5 = 9,600` 次刷新/日；1,000 名用户连续在线 24 小时则约为 288,000 次/日，已经超过 Workers 免费请求额度。实际还要加入启动、重试、管理和攻击流量。续租不应每次更新同一条心跳记录，避免无意义的 D1 写入。

费用控制要求：设置请求/错误率/配额告警、每请求 CPU 上限、应用限流与紧急停止签发开关；限制管理批次、请求体和查询扫描范围。在核对资料中没有确认“付费计划总账单到某金额必然硬停止”的保证，因此预算告警和 CPU 上限不得宣传为总账单硬封顶。免费配额不足、云端故障或成本熔断都进入已有 lease 的离线策略，而不是删除客户数据。

### Ed25519 与 Secrets

Workers `crypto.subtle` 官方支持标准 `Ed25519` 的签名、验证和密钥导入/导出；可使用它或基于它的标准库实现。不要选择旧的 `NODE-ED25519` 私有算法名作为新协议。[Workers Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/)

生产敏感值放入 Workers Secrets，不放 `wrangler` 的 `vars`，不进入 Vite 的 `VITE_*`、前端包、安装包、Git 仓库或截图日志。官方明确要求本地 `.dev.vars` / `.env` 不提交到 Git；密钥添加命令还可能触发部署，应由授权管理员在生产上线阶段执行，本阶段不执行。[Workers Secrets](https://developers.cloudflare.com/workers/configuration/secrets/)

要求三个独立秘密，不能复用：

- 授权签名用 Ed25519 私钥：只在服务端 Secrets 使用；客户端只内置公钥和允许的 `kid`。
- 刷新凭据用 HMAC 密钥：只生成/验证刷新 handle，不能用于签署授权 JWT。
- 管理员令牌：只能在受控的运维命令或管理端使用，不能写进普通客户端；Cloudflare 部署 API token 也应独立且最小权限。

未来生产密钥生成、备份、轮换和应急吊销需要单独授权与运维流程。本仓库只保存示例变量名，不保存生产秘密。测试密钥不能进入真实销售环境。

## 4. 计时规则：小时 / 天是绝对经过时间

默认商品可以是 1 小时、6 小时、1 天、7 天，对应 `durationSeconds` 为 3,600 / 21,600 / 86,400 / 604,800。这里的“天”固定为 86,400 秒，不是客户时区的自然日，也不受夏令时影响。管理员发码时配置期限，客户端无权提交任意期限或更改到期时间。

首次服务器成功绑定设备时，原子写入：

```text
activatedAt = serverUtcSeconds
licenseExpiresAt = activatedAt + durationSeconds
leaseExpiresAt = min(serverUtcSeconds + leaseSeconds, licenseExpiresAt)
```

数据库记录 `activatedAt` 与 `licenseExpiresAt` 后不可被普通激活重试或刷新重写。重复启动、卸载重装、重新输码、断网、设备时间改变，都不能重新赠送完整时长。首次激活响应在网络中丢失时，同设备重试返回已有绑定与相同绝对到期时间，而不是重新开始计时。

本原型默认 `leaseSeconds = 900`（15 分钟），管理接口最多接受 3,600 秒；实际签发始终受绝对到期时间截断。例如 1 小时卡只剩 4 分钟，即使请求 15 分钟 lease，也只允许剩余 4 分钟。`now >= licenseExpiresAt` 或 `now >= exp` 即到期，边界不能多给一个完整刷新窗口。15 分钟和 60 分钟不是“产品授权时长”，只是已有合法授权的最大离线凭证期限。

以后如提供付费续期，必须是单独的受保护管理操作，并明确新截止时间；`/refresh` 永远不等同于续费、延长商品时长或重新激活。

## 5. 最小服务契约

以下为本原型的目标契约；实现完成后应由自动化契约测试固定。`plan: "pro"` 当前只是标识，不代表已确定收费功能清单。

| 接口 | 输入 / 身份 | 行为 |
| --- | --- | --- |
| `POST /v1/admin/licenses` | 独立管理员 Bearer；`duration: { value, unit: "hours" \| "days" }`、`leaseSeconds`、`plan` | 创建未激活的一设备许可；响应只在发码时返回明文 code |
| `POST /v1/activate` | `code`、不透明 `deviceId`、随机 `nonce` | 验证 code 摘要；原子首次绑定，或同设备幂等返回；签发 lease 和该绑定的刷新 handle |
| `POST /v1/refresh` | `licenseId`、`deviceId`、`refreshToken`、新 `nonce` | 核验刷新凭据、设备、撤销状态和绝对期限；签发新的短 lease，但不改绝对期限 |
| `POST /v1/admin/licenses/:id/revoke` | 独立管理员 Bearer；必要的操作原因 / 幂等标识 | 标记撤销，后续激活和刷新拒绝；已离线 lease 不可能被即时远程抹除 |

激活码至少包含 128 位安全随机熵，建议 32 个随机字节；可用明确约定的 Base32 或十六进制编码，显示分组不减少熵。服务端只存规范化 code 的 SHA-256 摘要和短显示后缀，并为摘要设置唯一约束。大小写、分隔符和前缀规范必须在生成器与校验器间一致，不能对大小写敏感的任意字符串随意 `toUpperCase()`。

刷新 handle 可以使用独立服务端秘密，对带域分隔前缀、无歧义编码的 `licenseId + deviceHash` 做 HMAC，以支持同设备激活重试恢复相同 handle。必须验证数据库许可仍有效；handle 本身不是无限期限许可证。后续如支持换绑，加入可轮换的 `credentialVersion`，使旧 handle 无效，并始终保留原绝对到期时间。

`deviceId` 在原型中只是随机安装标识，`deviceHash = SHA-256(deviceId)`；它不是硬件证书，更不是不可克隆的机器码。刷新 handle 或整份客户端状态被复制后，攻击者可能伪装成同设备。设备密钥证明、系统凭据库与原生绑定是后续加固项，不能在尚未实现时宣传已具有这些能力。

### 签名凭证

使用固定算法的 JWT/JWS：`alg = EdDSA`，实际密钥曲线为 Ed25519，按 `kid` 选择已允许的公钥。原型声明如下：

| Claim | 校验要求 |
| --- | --- |
| `iss` | 必须等于 `svga-editor-pro-licensing` |
| `aud` | 必须包含预期产品 `com.svga.editor.pro`，不能跨产品复用 |
| `sub` | 许可 ID，不是明文激活码 |
| `iat` / `nbf` | 服务器 UTC 秒，不能接受客户端自报签发时间 |
| `exp` | 当前 lease 截止 UTC 秒，必须不大于 `licenseExpiresAt` |
| `licenseExpiresAt` | 首次激活得到的不可被刷新延长的绝对截止 UTC 秒 |
| `deviceHash` | 必须与当前客户端绑定标识匹配 |
| `nonce` | 与本次请求的随机挑战一致；在线响应不能把历史响应当作新授时 |
| `plan` | 服务端允许的计划标识，当前为 `pro` |

禁止接收 `alg: none`、允许攻击者任选算法、根据 token 内任意 URL 下载公钥，或者仅 Base64 解码而不验签。客户端校验签名后仍要校验产品、时间、设备和字段类型；签名有效但已经过期的 token 仍无效。JWT 内容可读，不能把秘密放进 claims。`nonce` 防止把旧响应当作新响应，但不能解决离线本地状态克隆或完整客户端补丁。

原型可以在 Node/Worker 测试环境验证签发与验签。商业桌面版的授权判断不能只藏在 React 按钮中；后续应在受控的原生入口进行一致校验，但仍必须承认原生二进制可被修改。

## 6. 并发、重试和数据一致性

默认单设备许可应由数据库约束和原子写入保证，而不是 `SELECT 未激活 → 客户端判断 → UPDATE`。推荐单行 compare-and-set：只有未激活、未绑定且未撤销的记录才能同时写入设备、首次激活时间和绝对到期时间；必须检查受影响行数。两个设备同时输同一码，只能有一个成功。

更新没有抢到时，从主库重新读：同设备返回已有许可；不同设备返回占用状态；已撤销或过期则拒绝。D1 的 `batch()` 可将多条预处理语句作为事务执行，语句失败会回滚整批；若启用读副本，授权决策需要 `first-primary` 会话或明确使用主库，不能用陈旧副本放行已撤销的许可。[D1 Database API](https://developers.cloudflare.com/d1/worker-api/d1-database/)

实现与测试必须满足：

- 首激活更新与席位占用不能分成无事务保障的多次请求；签名只能使用已提交的记录。
- 首激活提交后签名或网络失败，同设备可重试，绝对截止时间保持不变；不因故障创建第二份授权。
- 管理发码需幂等请求标识或明确禁止盲目自动重试。只存 code 摘要意味着响应丢失后不能查询出原明文；应查明是否创建成功，再撤销重发，而不是假称可以恢复原码。
- 刷新重复请求可以产生新 lease，但相同 `licenseExpiresAt` 必须一直保留；不能凭过期 JWT 单独续租，必须有有效刷新凭据并查询服务器许可状态。
- 数据库暂不可用时返回可重试错误，不能返回“授权有效”或“激活成功”。对授权查询不使用长期 CDN 缓存，响应设置 `Cache-Control: no-store`。
- 状态码应区分格式错误、凭据不匹配、设备占用、明确到期/撤销、限流和暂时故障；外部错误不返回 SQL、堆栈、私钥或令牌。对未认证的错误避免泄露码是否存在。
- 使用参数绑定；校验 JSON 大小、字符串长度、整数正数、允许的计划、时长乘法溢出和 lease 上限。默认拒绝未识别的方法和路径。

## 7. 限流、隐私与运行日志

激活入口是公开攻击面，生产上线前必须具有限流。建议分别限制 IP、code 摘要和设备摘要，管理员入口独立限制；对同公司 NAT 下正常用户保留合理容忍度，不能只依赖 IP。请求体、批次数量、响应大小和重试频率也需要边界。

Cloudflare Rate Limiting binding 的计数是区域级、最终一致的限流信号，不是全球精确计费或席位账本。可以用于阻挡滥用，但不能替代 D1 的一设备原子约束。[Workers Rate Limiting](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)

“no-log”在此指不记录授权秘密或用户内容，不是宣称云平台没有任何运维数据：

- 激活码和刷新 token 只放 HTTPS 请求体或合适的授权头，不放 URL 查询参数。
- 不 `console.log(request)`、不记录完整请求/响应、Authorization、JWT、设备原标识或发码明文；异常捕获和监控系统也要脱敏。
- 可以记录随机请求 ID、状态类别、延迟和去标识的计数。管理审计记录操作者、许可 ID、动作和时间，不记录码本身。
- 如为滥用控制暂存 IP 或标识摘要，需限定用途和保存周期，并在隐私说明中披露；不要默认永久保存。
- 绝不为反破解扫描、上传、加密、删除或修改用户工程、个人文件、浏览记录或其他应用数据，也不关闭安全软件。

## 8. 离线宽限、错误恢复与用户成果保护

仅在已经验证过的 lease 范围内离线使用，不额外赠送新的离线时长。在线刷新失败时保留原凭证和原 `exp`，使用带随机抖动的指数退避；遵守 `Retry-After`，取消过期请求，避免多个窗口或唤醒同时刷新。明确收到撤销或到期响应不应伪装成普通断网；但客户端仍须保护已有成果。

可信时间可以从已验签的服务器响应建立，并在同一运行会话中用单调时钟推进；同时检测显著的本地回拨、过大的前跳、休眠恢复和跨重启变化。异常时提示联网重新核验，不应将系统时钟问题直接判为欺诈。跨重启保存的“最高已知时间”只能提高回拨成本，恢复虚拟机快照或整体复制仍可能绕过。

授权状态与文档状态必须分离：

1. 接近离线凭证或商品到期时提前提示，并显示用户本地时区的截止时间；内部仍使用 UTC 秒。
2. 到期、失联超时或校验失败后，不突然关闭程序、不丢弃撤销历史、不清空内存文档。
3. 保留查看、保存工程副本、导出已有成果和数据迁出的能力。已经开始的导出按开始时的授权快照完成，不能中途产生损坏文件或附加未告知水印。
4. 若未来限制新建、高级处理或新的付费操作，应明确列出范围；不得把“交钱才能取回用户已有作品”作为恢复机制。
5. 完整授权过期与临时云服务失败使用不同提示；有可用授权时允许通过重新联网恢复，不要求用户反复购买。

这样的成果保护会牺牲部分强制性，是有意的产品约束。本阶段尚未决定或启用收费 gate，不得借服务原型偷偷改变现有用户的编辑与导出权限。

## 9. 无自建服务器仍需哪些准备

- 一个由产品方控制、开启 MFA 的 Cloudflare 账户，以及独立的开发/生产环境、D1 数据库、Secrets、域名路由和运维负责人。
- 开发验证可用 `workers.dev`；Cloudflare 官方建议生产服务使用 route 或自定义域名。自定义域名需要可管理的 Cloudflare zone；购买域名和托管套餐是另外的费用与授权，不是本阶段自动执行的步骤。[workers.dev 使用范围](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)；[Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)
- 确认请求预算、账单告警、过载处置、数据库恢复与秘密轮换。免费层的服务中断风险需要被纳入售后承诺，不能将“无自建机房”解释成“无人维护且永久免费”。
- 面向中国大陆用户，在实际目标地区、运营商、企业代理和无 VPN 条件下测试 DNS、TLS、激活、刷新、下载与离线恢复。普通全球服务的可达性不能由开发机器上的一次成功推断；Cloudflare China Network 是另一个特定服务，不能假设注册免费 Workers 就获得其能力。[Cloudflare China Network](https://developers.cloudflare.com/china-network/)

### 安装包与更新分发

R2 可以作为公开安装包和更新清单的分发端，但公开 bucket 中的内容应被视为任何人可下载，不能放授权秘密。生产下载使用自定义域名；`r2.dev` 仅供非生产测试且会限流。[R2 Public Buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/)

R2 Standard 的核对日免费量是每月 10 GB-month 存储、100 万 Class A 操作和 1,000 万 Class B 操作，直接 R2 出网无传输费用；超额存储/操作或其他计费服务仍可能收费，不能概括为所有下载成本永远为零。[R2 Pricing](https://developers.cloudflare.com/r2/pricing/)

GitHub 可以继续负责构建、留存源代码和公开版本信息，R2 为可选分发路径；两者都不应决定授权是否过期。安装包哈希、平台代码签名和更新签名应独立于授权 JWT 密钥。不要在同一个公开对象存储里混放安装包、数据库备份和客户码单。

## 10. Keygen Cloud 托管对照

| 方案 | 适合点 | 需要承担的工作 |
| --- | --- | --- |
| Workers + D1 | 控制规则与数据结构；小规模可在已知免费配额内试验 | 自己实现并维护激活、并发、签名、管理、监控、恢复与兼容性 |
| Keygen Cloud | 已有许可、机器激活、限期授权和离线许可相关 API | 开立服务账户、评估收费与数据处理、配置策略、集成并实测桌面端 |
| Keygen 自托管 / Relay | 可满足特定离线或客户网络部署需求 | 仍需要运营一个服务或网关，不符合“完全不维护服务器”的最简单目标 |

Keygen 官方把机器资源创建/删除用于激活/停用；离线许可文件是签名快照，官方建议设置到期以便最终反映撤销等状态。采用托管商也不能绕过客户端补丁和离线撤销延迟的物理边界。[Keygen 机器激活](https://keygen.sh/docs/activating-machines/)；[Keygen 离线密码学](https://keygen.sh/docs/api/cryptography/)

Keygen Cloud 本项目适用档位的确切价格：**unknown**。核对时官方页面使用交互式分级展示，未取得可据以承诺的完整档位金额；不要引用历史博客报价或误把自托管许可、附加域名服务价格当成 Cloud 订阅价。正式选型前按活跃授权规模向官方确认计划、配额、地区可达性与费用。[Keygen Pricing](https://keygen.sh/pricing/)

当前建议优先验证 Workers + D1 原型；若团队不愿长期维护授权服务、管理台和故障处理，再以 Keygen Cloud 报价及接入验证结果作成本对照，不在没有账户与预算确认时购买任一服务。

## 11. 商业上线前的验收清单

- [ ] 激活与刷新协议测试覆盖签名错误、错误公钥/算法、错误产品/设备/nonce、过去和未来时间、字段类型与边界。
- [ ] 两设备并发首次激活只成功一个；同设备网络失败重试不会改变 `activatedAt` 或绝对到期时间。
- [ ] 1h / 6h / 1d / 7d 卡正确换算；所有刷新 lease 都不越过绝对截止；撤销立即阻止新的签发。
- [ ] 回拨、休眠、跨时区、离线重启、代理错误、D1 限额、服务失联和密钥轮换都经过端到端测试，并记录不能防止的克隆情形。
- [ ] 请求限流、成本告警、错误脱敏、管理员鉴权、数据库备份恢复和应急停止签发已经验证。
- [ ] 原生校验、客户端可信公钥配置、系统级凭据保存和与真实 Worker 的 HTTPS 集成已实现，而非仅有网页状态开关。
- [ ] 到期不会损坏或扣留用户作品；现有成果可以保存和导出；收费功能范围、到期规则与售后支持已写清楚。
- [ ] 目标客户所在地区的网络可达性已实测；没有用理论免费配额代替生产容量测试。
- [ ] 正式支付、订单/退款/续期处理及销售规则另行设计、评审和授权；没有仅凭“能发码”就开始收费。
- [ ] 生产部署、生产密钥和账户预算由负责人确认后再建立；本文和本轮实现均不代表这些步骤已经完成。

本方案的可交付目标是可验证、可维护、对用户成果友好的限时授权基础，而不是“绝对防破解”的销售承诺。
