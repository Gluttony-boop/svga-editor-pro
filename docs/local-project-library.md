# 自动恢复与最近工程（本机副本）

本机工程库让设计师在重新打开应用后继续编辑，并为未保存修改保留恢复机会。它使用与手动保存相同的 [`.svgaproj` 工程格式](project-format.md)，不是只能播放的 SVGA 导出，也不是云备份。

## 怎么使用

1. 工具栏点击“恢复 / 最近”，或在底部点击“本机副本设置”。启动时发现已有恢复副本也会出现“查看恢复副本”提示，不会自动替换当前文档。
2. 在“未保存恢复副本”中选择“打开本机副本”。若当前工程有未保存修改，先处理保存、放弃或取消；取消会保留当前工程和原副本。
3. 恢复后可以继续改图层、关键帧、文字和图片，按 Ctrl+S 另行保存为工程文件。打开本机副本不会取得原磁盘文件的自动覆盖权限，也不会仅因打开就删除原副本。
4. “最近工程”保存已打开或保存过的 `.svgaproj` 的本机内容副本。它不是文件路径快捷方式，不跟随磁盘文件后续更新；重新打开后保存需要重新选择路径。
5. 若只想抢救副本而不打断当前编辑，选择“下载工程”。它不会替换当前文档；网页下载仍需要自行确认文件已经落到下载目录。

恢复的是归档中的编辑状态，不恢复跨会话撤销历史。重新打开后建立新的撤销历史；字体和图片/音频解码的平台限制与手动工程文件相同。

## 自动保存何时发生

首次创建本机库时，“自动保留未保存修改的恢复副本”和“保留最近工程的本机副本”默认开启，两个开关可以独立关闭。关闭只停止后续写入，已有副本不会自动删除；重启或在应用内清空副本也不会重新开启已关闭的开关。

对有未保存修改的工程，自动恢复默认在最后一次稳定编辑后等待约 3 秒，连续两次后台尝试至少间隔约 15 秒。播放游标移动不算编辑；拖拽、变换或文字输入事务未完成时，不会替用户提交草稿、暂停播放或增加撤销步骤。状态栏显示排队、写入、成功或错误，可使用“立即备份”或“重试本机备份”。

“已保存本地恢复副本”不等于磁盘工程已保存。Ctrl+S 确认写盘成功后，才清理当前文档对应的恢复副本；最近工程缓存维护失败会单独提示，不会把实际写盘成功误报成保存失败。网页只发起下载但无法确认落盘时仍保留未保存保护。

浏览器关闭、应用崩溃、强制退出和系统断电不保证异步压缩或写入完成，刚刚操作的内容可能尚未备份。不要把它当成“零丢失”承诺；重要节点仍应主动保存 `.svgaproj` 并保留外部备份。

## 数量、容量与清理

| 项目 | 规则 |
| --- | --- |
| 未保存恢复副本 | 最多 5 份，不自动淘汰；满额会拒绝新的恢复副本，原记录仍可更新 |
| 最近工程副本 | 最多 8 份；超过数量或容量时自动淘汰较旧的最近缓存 |
| 整个本机库 | 归档字节合计最多 256 MiB；恢复与最近共同占用 |
| 单份归档 | 必须大于 0，最大 128 MiB；仍需满足工程格式的内容校验 |

容量不足时先计算能否通过淘汰最近缓存完成写入。不能通过淘汰最近缓存腾出空间时，明确拒绝新写入，不删除恢复副本。删除最近缓存与新副本写入处于同一个数据库事务中，浏览器实际报配额不足或事务中止时一起回滚，不会先丢旧副本再报保存失败。浏览器/系统自己的配额可能比上述上限更低。

单份“删除”和“清空本机副本”均需确认，确认前可以取消；只作用于本机副本，不删除磁盘工程、不清空当前编辑画布。删除不可撤销，尤其恢复副本可能是未保存修改的唯一备份，请先下载。清除后不会立刻为同一份未变化的编辑状态重新生成副本；后续新编辑或明确手动备份才继续。

最近工程是可淘汰缓存，不应作为唯一交付存档；相同磁盘文件的不同打开会话也可能产生不同副本。列表按副本更新时间排序，显示的时间是本机时间，不代表文件原始修改时间或云端同步时间。

## 隐私与存储边界

- 内容只写入当前浏览器或桌面 WebView 的 IndexedDB，没有素材上传、云同步或分析埋点。
- 索引只保留内部 ID、类别、显示名称、更新时间、大小和修订号；不保留原文件绝对路径或文件句柄。工程内容仍包含图片、音频、文字等用户素材。
- **归档和本机副本没有加密。** 能访问该操作系统账号、浏览器配置或应用数据的人可能读取内容。敏感项目可关闭两个开关，并确认清除已有副本；不要将私钥、激活密钥或账号密码放入工程。
- 数据按浏览器/WebView 用户配置和页面来源隔离。`localhost` 与 `127.0.0.1`、不同端口、不同浏览器配置以及桌面应用与网页之间不保证共用一个库；换设备也不会自动出现副本。
- 清理站点数据、浏览器或应用数据、重建用户配置、隐私模式结束以及系统/浏览器存储回收，都可能让副本丢失。应用内“清空副本”会保留开关；从外部删除整个数据库也会删除开关，新建库会使用首次默认值。
- 同一来源的多个窗口共享同一库时，清除、删除或设置变更会使旧写入代次失效，即使没有 BroadcastChannel，也不会因较早启动的压缩任务而把旧内容重新写回来。

## 出错时如何处理

1. 保留当前画面，先手动保存重要工程文件。自动恢复错误不应要求用户放弃仍在内存里的工作。
2. 配额或恢复份数满额：先下载需要的旧副本，确认可用后再删除不需要的记录，随后“重试本机备份”。
3. 存储被禁用、连接被其他窗口升级或异常关闭：检查隐私设置、关闭其他编辑器窗口，再重新打开当前应用。不会静默改用新空库冒充恢复成功。
4. 设置或个别记录损坏：界面明确报错，不展示一个假空列表，也不自动重置开关。确认不再需要本机内容后，可手动“清空本机副本”；损坏设置修复时两个开关一律关闭，需要主动重新开启。
5. 数据库版本更高或物理表结构不兼容：当前版本拒绝读写与清空，保留原数据供兼容版本处理。不要通过删除整个浏览器配置来尝试修复仍需抢救的副本。

## 开发约束与验证

`createProjectLibrary()` 封装 IndexedDB，采用 `idb`。归档压缩、校验与资源解码在上层执行，仓库只保存不可变 Blob 字节和白名单元数据。

- `put(record, expectedEpoch)` 在同一读写事务内验证设置、代次、revision、类别与配额；只在事务完成后返回 `stored` 并通知。`stale` 和 `disabled` 不是写入成功。
- `remove` 即使找不到 ID 也会增加 epoch，因为删除时可能仍有同 ID 的首次压缩任务未写入。不能将这个操作优化为无影响的 no-op。
- `clear` 和 `configure` 与写入共用两张表的事务锁，不因跨窗口并发而丢失开关或配额变化。旧 revision 不会覆盖新内容，同 ID 不允许换类别。
- 订阅通知或广播发送失败不能改变已提交事务的结果。版本升级或异常关闭后当前实例停用，不自动删库或重连；由用户重新打开应用。
- 使用原生 Blob 的大小 getter 做品牌与字节数校验，不信任普通对象或覆盖后的 `size`。显示名称拒绝路径、控制字符、Windows 保留文件名和尾部点/空格。

定向执行：

```powershell
npm run test:run -- src/core/project-library.test.ts
```

该套测试通过真实 `fake-indexeddb` 事务验证重开持久化、白名单、边界值、恢复不淘汰、最近淘汰、256 MiB 容量、配额失败回滚、请求成功但事务中止、双实例并发、代次防复活、损坏设置/记录、关闭/升级/异常终止和通知隔离。阻塞回调测试向真实打开请求注入阻塞事件，再让其真实完成以检查迟到连接是否释放；它不等同于真实浏览器发生过该故障。容量测试共享 32 MiB 的 Blob 底层数据，不读取数百 MiB 归档内容。浏览器交互和桌面 WebView 的存储可用性仍需独立验收，不能用内存数据库测试代替。

### 2026-09-21 验收记录

编辑器全量 1,536 项测试通过；其中本机库 107 项、恢复调度 42 项、无副作用快照 14 项、保存完成结果分离 5 项、工程库组件 17 项。调度测试使用真实 Store 与本机库事务，含 3 秒防抖 / 15 秒节流、清理后的第一次编辑、排队最近工程的代次、停止后解除等待、串行编码及事务输入隔离。组件测试是静态渲染检查，不冒充交互测试。

另用 Playwright 在独立 Edge 配置、生产构建中完成以下真实流程：

- 打开带关键帧、换图和模拟文字的工程，修改图层位置与文案，备份后刷新。启动提示发现恢复副本，手动恢复后仍提示未保存；800×844、同一帧画布的像素摘要与刷新前一致。
- 当前工程未保存时打开另一份本机副本：取消回到工程库，内容不变、按钮恢复可用；确认弹窗聚焦且 Tab 不进入背景编辑器。
- 向测试库加入坏归档后打开，当前画布及未保存修改保持不变，工程库内显示可见错误。
- 下载恢复副本为真实 `.svgaproj`，在另一标签页从文件重新打开，图层位置、关键帧与画布像素保持一致，并生成最近工程记录。
- 在测试库注入损坏设置，初次读取失败时仍允许明确二次确认清空；取消保留记录。确认后同来源另一标签页收到清理，当前文档不变，两个记录开关关闭；关闭状态的新编辑不写副本，主动开启后再次编辑可正常备份。
- 注入浏览器存储拒绝写入，删除失败保留确认并将焦点返回取消按钮。模拟工程写入失败时不切换文档；模拟工程写入成功、但缓存配额失败时显示独立警告，不误报工程未保存。

在开发构建及 Store 测试中另外确认：备份不暂停播放、不增加历史；文字输入聚焦期间库记录不变，Esc 可完整回到原文案。所有存储损坏、配额和写盘错误均为测试故障注入，不代表真的耗尽磁盘或触发过操作系统崩溃。测试截图/归档位于忽略的 `output/playwright/`，没有修改用户磁盘工程。

TypeScript、ESLint 和 Web 构建通过；生产页面控制台未出现意外错误。Windows 原生 WebView、系统强杀/断电恢复以及原子文件替换执行测试仍待完整桌面构建环境验收，不据此承诺最后一刻的修改零丢失。
