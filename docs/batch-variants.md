# 批量文案预检与队列基础（当前版本）

更新时间：2026-09-25。入口：右侧「插槽」→「批量文案预检…」。当前已上线的是本机文案规则预检和报告导出，不是完整批量 SVGA 生成器。

当前版本已加入批量变体的安全数据层和文案预检入口，代码位于 `src/core/batch-variants.ts`。它是后续“导入清单 → 逐行预检 → 串行导出 → 失败重试 → 中断恢复”流程的基础。

## 已实现

- 项目级模板约束：每个可替换 Key 明确是文字还是图片，并可设置最大文字长度、允许图片格式、字节大小和像素尺寸。
- CSV 清单解析：使用 [Papa Parse](https://www.papaparse.com/docs) 5.7.0 处理引号、逗号和多行单元格；默认只把 id 当编号列，不改写 name、variantId、变体或真实 SVGA Key 的空格。核心 API 可显式指定编号列或传 null 保留 id Key；界面遇到 id Key 时应选嵌套 JSON。CSV 记录号包含表头，多行单元格算一条，不等于物理行号。
- JSON 清单解析：支持数组或 `{ "rows": [] }`，图片只能使用内嵌 Data URL 对象，不接受本地路径或远端 URL。
- 逐行预检：报告行号、精确 Key 和失败类别，包括缺 Key、缺值、未知 Key、超长文案、图片格式/大小/尺寸错误和重复编号。文案内容不写入错误摘要。
- 队列状态机：`queued / running / succeeded / failed / cancelled`；成功产物保留文件名、大小和 SHA-256，失败项保留定位信息。
- 恢复与重试：重启解析队列时只把中断中的 `running` 恢复为 `queued`；成功项不重跑、不覆盖；“仅重试失败项”不会改变成功项。
- 队列 JSON 有 8 MiB、1 万行和严格字段/状态一致性限制；规范化模板内容变化会拒绝旧队列。templateSignature 只是内容比较标记，不是数字签名。成功产物记录不证明真实文件存在；执行适配层还需核对文件与源工程修订。

## 预检入口

「批量文案预检」支持选择当前可模拟文字的 Key、导入/粘贴 UTF-8 CSV 或 JSON、填写 Unicode 码点上限、只看问题行，以及导出不含原始文案/图片的 JSON 报告。预检通过只说明清单结构、Key、必填项和文字长度规则通过；不表示字体宽度、像素裁切、SVGA 产物或目标播放器通过。

## 当前尚未实现

JSON 推荐数组项为 {"id":"001","values":{"title$":"昵称","name":"欢迎"}}。嵌套 values 内的 id/name/values/constructor/__proto__ 都作为精确资源名，不静默丢弃；重复 JSON 字段明确拒绝。图片对象即使格式头和字节长度正确，仍明确返回「尚未真实解码」，不能进入可执行队列。

预检不修改工程、不增加撤销记录。内容变化后报告失效，选择保存位置期间也再次核对输入。关闭弹窗会丢弃本次清单；报告含编号和 Key，分享前仍须检查是否包含客户信息。

模板另存/选择 UI、图片真实解码预检、文件夹或 ZIP 输出、逐项调用 SVGA 导出器、实际磁盘持久化适配和中断后自动发现入口仍需接入。当前不能把队列 JSON 当成已经写入磁盘的批量任务，也不能宣传批量导出已经完成。

## 设计边界

批量导出应在预检通过后使用与单件导出完全相同的 `buildProjectSvga` 路径；每项完成后再写入产物和摘要。任何失败只能标记该项，不应回滚或覆盖其他成功项。动态文字仍需根据模板选择“动态接入清单”或“固定字形写入”，不能把设计预览截图当作动画本体。
