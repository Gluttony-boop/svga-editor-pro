# 批量文案预检与批量交付（当前版本）

更新时间：2026-09-29。入口：右侧「插槽」→「批量文案预检 / 恢复任务…」。已实现本机文案预检、连续应用到画布、串行批量交付，以及可手动保存/重开的 `.svgabatch` 任务文件；图片批量执行、模板库与任务自动备份尚未接通，不是完整 M3。

当前版本已加入批量变体的安全数据层和文案预检入口，代码位于 `src/core/batch-variants.ts`。它是后续“导入清单 → 逐行预检 → 串行导出 → 失败重试 → 中断恢复”流程的基础。

## 已实现

- 项目级模板约束：每个可替换 Key 明确是文字还是图片，并可设置最大文字长度、允许图片格式、字节大小和像素尺寸。
- CSV 清单解析：使用 [Papa Parse](https://www.papaparse.com/docs) 5.7.0 处理引号、逗号和多行单元格；默认只把 id 当编号列，不改写 name、variantId、变体或真实 SVGA Key 的空格。核心 API 可显式指定编号列或传 null 保留 id Key；界面遇到 id Key 时应选嵌套 JSON。CSV 记录号包含表头，多行单元格算一条，不等于物理行号。
- JSON 清单解析：支持数组或 `{ "rows": [] }`，图片只能使用内嵌 Data URL 对象，不接受本地路径或远端 URL。
- 逐行预检：报告行号、精确 Key 和失败类别，包括缺 Key、缺值、未知 Key、超长文案、图片格式/大小/尺寸错误和重复编号。文案内容不写入错误摘要。
- 队列状态机：`queued / running / succeeded / failed / cancelled`；成功产物保留 SVGA 或交付 ZIP 的安全文件名、大小和 SHA-256，失败项保留定位信息。
- 恢复与重试：重启解析队列时只把中断中的 `running` 恢复为 `queued`；成功项不重跑、不覆盖；“仅重试失败项”不会改变成功项。
- 队列 JSON 有 8 MiB、1 万行和严格字段/状态一致性限制；规范化模板内容变化会拒绝旧队列。templateSignature 只是内容比较标记，不是数字签名。成功产物记录不证明真实文件存在；执行适配层还需核对文件与源工程修订。

## 预检入口

「批量文案预检」支持选择当前可模拟文字的 Key、导入/粘贴 UTF-8 CSV 或 JSON、填写 Unicode 码点上限、只看问题行，以及导出不含原始文案/图片的 JSON 报告。预检通过只说明清单结构、Key、必填项和文字长度规则通过；不表示字体宽度、像素裁切、SVGA 产物或目标播放器通过。

## 应用一条文案到画布

预检结果每行提供「应用并收起」。只允许应用通过规则检查的记录；有问题的行、过期报告或保存中的报告不能应用。点击后替换该记录全部 Key 的文案并启用文字显示，收起弹窗回到画布；多 Key 合并为一次历史，可用 Ctrl/Cmd+Z 一次撤销，也可重做。

已有字体、颜色、对齐、偏移、文字显示范围、图片替换和导出模式保留。没有文字配置的 Key 使用默认样式，默认仅模拟。应用本身不会生成文件，也不将已有 preview 模式改为 bake；若需要导出的 SVGA 包含字形，仍须设置文字范围并显式选择「写入 SVGA」后导出。画布显示仍受原遮罩、当前帧及图层可见性影响。

应用前再次检查完整清单，防止漏掉重复编号；提交时再次检查工程输入、可用 Key、文字长度和样式。任一 Key 无效，整条记录都不写入；正在输入或变换的草稿不会被隐式提交。相同内容重复应用不新增历史。

收起弹窗会保留清单、规则、筛选和预检结果。插槽面板提供「上一条文案／下一条文案」，按清单顺序只切换通过行，每次切换独立可撤销；尚未应用时可从首条开始。上次应用编号仅为操作记录，不保证当前工程仍与该行相同。修改工程或撤销后停止切换，需展开清单重新预检；播放、逐帧查看、缩放和切换检查器标签不会清掉清单。画布尺寸调整保留清单但会使报告过期。

「丢弃清单」只释放清单与预检状态，不撤销已经应用的文案。清单仅存在当前组件会话内，不写入工程或本地恢复数据库；刷新、切换源工程或卸载工作区会丢失。预检报告不含原文案，不能用于恢复清单。

## 批量文字交付

1. 先设置文字样式与显示范围，再导入清单并预检。可逐条「应用并收起」抽样核对画布；长度规则不能预测实际字宽或裁切。
2. 全部记录通过后，在「3. 批量文字交付」明确选择本批所选 Key 的模式，默认不替用户选择：
   - **动态接入**：所选文案不写入 SVGA；每条交付包的 `slots.json` 和设计预览提供文案及样式，开发端须适配目标播放器。
   - **固定字形**：所选文案写入 SVGA 的图片，整段动画保留，播放器不能再动态改这些字。首次使用时按当前 Key 尺寸建立完整文字框与参考尺寸，已有扩容设置保留。
3. 点击「生成批量交付」。工程冻结一次；每行复用 `generateDeliveryBundle → buildProjectSvga` 单件路径，完成优化、真实产物回读、来源 Key 与文字模式核对、双预览及报告。其他未选 Key 保持工程设置，跨 Key 去重关闭；原工程、画布和撤销历史不被批量任务修改。
4. 可「停止后续生成」，已成功的字节仍保留；之后可「继续已停止项」或「仅重试失败项」。重试使用原任务的工程与清单快照，不重跑成功项，也不混入后续编辑。修改后要生成新版，先保存已有结果，再「释放结果 / 新建任务」并重新预检。
5. 每条可「查看产物」，对照实际 SVGA 与设计模拟并单独保存；「保存已完成 ZIP」汇总所有成功交付。部分成功也可保存，但汇总 `manifest.json.complete=false`，失败/停止项没有产物，不会伪装全部完成。

汇总 ZIP 内为 `variants/00001.zip` 等独立交付包、`manifest.json`、`README.txt` 和 `checksums.sha256`。每个独立包包含 `animation.svga`、Key 与资源清单、实际/设计预览和离线报告；编号到文件路径以汇总清单为准，不把客户编号或资源 Key 当文件路径。默认不附可编辑源工程；仍含文案、编号、Key 和可能未引用的资源，分享前核对权限。

单批最多 100 行，成功包与保留预览累计最多 256 MiB，超限行失败但已有结果保留。未保存的任务只在当前会话内存保留；收起弹窗、切换检查器标签或工程不会清空已冻结的任务，但新文案预检须使用新工程会话。刷新、关闭程序或丢弃清单会丢失未保存内容。浏览器关闭时提示未保存结果/任务进度，原生关闭/安装更新在生成、保存或读取任务期间被同步门卫阻止。保存按钮保留用户手势，取消保存仍可重试；浏览器下载接口成功不等于用户已确认下载落盘。

当前帧双预览不是全帧、裁切、字体许可、目标 SDK 或真机性能证明。沿用的 PNG 量化/WebP 等优化可能引入像素差异，应查看包内报告与「优化提醒与未测项」。SHA-256 仅证明内容一致性，不是数字签名。

## 保存与恢复批量任务

1. 生成过程中先按「停止当前任务」，等待当前执行退出。已成功项保留，失败和停止项分别记录。
2. 按「保存任务文件（可继续）」，确认 `.svgabatch` 已下载到磁盘。没有成功产物的任务也可以保存。
3. 下次启动后进入「插槽 → 批量文案预检 / 恢复任务… → 打开任务文件…」。不需要先导入原 SVGA，也不会替换当前画布。
4. 校验通过后可查看已保存的预览、展开每条「任务文案」、下载旧结果，并选择「继续已停止项」「继续待执行项」或「仅重试失败项」。重做未完成项使用文件中的工程、文案和输出模式，已成功条目不重跑。续跑后需要再次保存任务文件。

任务文件和交付 ZIP 用途不同：任务文件包含自包含源工程快照、全部原始文案、模板规则、队列状态/尝试次数，以及成功交付包和双预览，未加密，请勿直接发送给客户。源素材不上传网络，字体文件不嵌入；跨机器继续时仍要核对字体可用性。当前表单中的未预检草稿、画布应用记录不属于冻结任务，不保存在此格式内。

输入校验失败或取消读取不替换旧任务；成功读取后，已有任务仍需确认才替换。文件仅在用户操作时读写，没有后台自动发现或崩溃恢复，恢复点到上次手动保存为止。交付 ZIP、预检报告、单独队列 JSON 都不能替代任务文件。

安全边界：固定魔数/版本、76 字节前缀（8 字节魔数、4 字节小端 JSON 长度、64 字节十六进制头摘要）、有界 JSON 清单及顺序二进制载荷；头与各载荷 SHA-256 均重新计算，重复 JSON Key、深层嵌套、未知字段、超限/截断/尾随字节、队列与产物不一致均拒绝。源工程沿用已有 `.svgaproj` 解压/路径/CRC/内容检查并重算源修订，不新增任意 ZIP 解压入口。头最多 9 MiB、内嵌源工程最多 128 MiB、全部结果与预览最多 256 MiB（总文件最多 393 MiB + 76 字节）；单个预览最多 32 MiB，限定静态 PNG、画布像素及块数量。

恢复的成功交付包视作不透明的旧字节，不在编辑器里执行或渲染内嵌 HTML 报告；仅显示通过格式/尺寸边界检查的 PNG。摘要只能检测损坏，不能证明可信来源或文案与 SVGA 的真实对应关系。旧结果在界面和再次导出的汇总清单中标为 `restored-integrity-only`，不声称本次重新回读或验证了原交付报告；本次新生成条目标为 `generated-in-session`。仅打开可信来源的任务。

## 当前尚未实现

JSON 推荐数组项为 {"id":"001","values":{"title$":"昵称","name":"欢迎"}}。嵌套 values 内的 id/name/values/constructor/__proto__ 都作为精确资源名，不静默丢弃；重复 JSON 字段明确拒绝。图片对象即使格式头和字节长度正确，仍明确返回「尚未真实解码」，不能进入可执行队列。

仅预检不修改工程、不增加撤销记录；主动应用才写入文案。内容变化后报告失效，选择保存位置期间也再次核对输入。报告含编号和 Key，分享前仍须检查是否包含客户信息。

模板另存/选择 UI、图片真实解码与批量替换、直接文件夹输出、任务自动持久化和中断后自动发现入口仍需接入。手动保存任务后可刷新重开续跑，不等于刷新前未保存的任务或崩溃前最新进度可恢复；不能将队列 JSON 或分享 ZIP 当成已经保存的可执行恢复任务。

## 设计边界

批量导出应在预检通过后使用与单件导出完全相同的 `buildProjectSvga` 路径；每项完成后再写入产物和摘要。任何失败只能标记该项，不应回滚或覆盖其他成功项。动态文字仍需根据模板选择“动态接入清单”或“固定字形写入”，不能把设计预览截图当作动画本体。
